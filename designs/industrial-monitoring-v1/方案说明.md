# 工业智能监控与巡检平台：活动告警列表原型

## 目标

在指标卡、实时趋势图和设备状态组件基础上增加 `alarm-list`，让现场操作员集中查看当前仍未恢复的 Active Alarm，并区分告警条件与数据可信度。

## 业务范围

- 数值 Data Point 达到组件 `alarmThreshold` 时产生阈值告警。
- Device State 等于 `2` 时产生设备故障告警。
- 收到明确恢复值后，告警从列表移除。
- Data Freshness 过期不清除告警，只标记“数据已过期”。
- 相同 `dataKey + 告警类型 + 阈值/状态码` 合并为一条。
- 设备故障排在阈值越界之前，同类保持页面组件顺序。

第一版只展示 Active Alarm，不保存告警历史，也不提供确认、删除或筛选。

## 默认组件

```json
{
  "id": "alarm-list-main",
  "type": "alarm-list",
  "position": { "x": 830, "y": 370 },
  "size": { "width": 520, "height": 300 },
  "props": {
    "title": "活动告警"
  }
}
```

## 视觉结构

- 头部显示组件标题和当前告警数量。
- 故障使用低饱和红色，阈值越界使用琥珀色。
- 每行显示告警类型、设备或 Data Point 名称、当前值与阈值，以及 Data Freshness。
- 列表区域内部滚动，不让组件随条目数量无限增高。
- 编辑器使用两条带“示例数据”标记的告警，运行态只显示真实活动告警。

## 空状态

- 尚未收到相关数据：`等待设备数据`
- 已收到新鲜数据且没有告警：`当前无活动告警`
- 已有告警但数据过期：保留告警行，状态改为 `数据已过期`

## 原型评审路径

1. 点击组件栏“告警列表”，确认只添加一个实例。
2. 修改组件标题。
3. 发布并进入运行态，查看等待状态和无告警状态。
4. 点击“触发告警”，出现一条阈值告警。
5. 点击 Device State 的“故障”，设备故障排在阈值告警之前。
6. 暂停上报 5 秒，确认两条告警保留并标记过期。
7. 点击“恢复正常”，确认列表回到无告警状态。

## 明确不做

- 告警确认、删除和处理流程
- 告警历史、分页和查询
- 可配置严重级别
- 迟滞区间或延时触发
- 后端告警事件、持久化或新的 WebSocket 消息
- AI 故障诊断

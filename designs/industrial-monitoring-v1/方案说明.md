# 工业智能监控与巡检平台：第一版设计方案

## 目标

第一版只验证一个核心架构判断：编辑态和运行态使用同一份页面 Schema，并通过同一套组件定义渲染。

## 用户

- 组态工程师：在编辑器中配置监控页面。
- 现场操作员：在运行态查看实时指标与设备状态。

## 本次设计范围

1. 编辑器主屏：组件栏、网格画布、属性面板、Schema 预览。
2. 一个可用组件：指标卡。
3. 属性修改：设备名称、指标标题、数据键、单位、小数位和告警阈值。
4. 原型交互：拖动指标卡、修改属性、复制 Schema、保存草稿、切换运行态。
5. 运行态：读取同一份 Schema，去掉编辑控件后渲染指标卡。

## 明确不做

- Vue 工程和真实组件实现
- 后端保存、版本管理和发布接口
- WebSocket 实时数据
- Electron 与小程序
- AI 诊断 Agent
- 文本、折线图、设备状态和告警列表组件

## 信息架构

```text
监控画面编辑器
├── 顶部栏：页面身份、保存状态、运行态预览、保存
├── 左侧组件栏：指标卡可用，其余能力锁定
├── 中央画布：页面布局与组件选中状态
├── 右侧属性栏：组件属性与 Schema 预览
└── 底部状态栏：画布尺寸、缩放和组件数量

运行态预览
├── 顶部栏：页面名称、数据连接状态、返回编辑器
└── 监控画布：只呈现组件，不出现编辑控件
```

## 视觉方向

工业工具式的克制设计：深石墨蓝画布、浅灰侧栏、青蓝交互色、绿色正常状态和琥珀色告警语义。强调精密网格、清楚层级和紧凑信息密度，避免赛博朋克、玻璃拟态和通用后台卡片堆叠。

## 后续开发时的验收条件

- 修改属性后，画布和 Schema 同步更新。
- 运行态读取保存后的同一份 Schema。
- 编辑态和运行态不各自维护组件协议。
- 未支持组件不会误导用户为已经可用。

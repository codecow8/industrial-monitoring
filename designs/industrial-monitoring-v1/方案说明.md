# 工业智能监控与巡检平台：运行态原型

## 目标

操作员在运行态选择一条 Active Alarm，手动点击“智能分析”，查看该告警的观测事实、可能原因、建议检查步骤和证据来源。原型用固定案例演示界面与状态；对应分析接口与 Vue 面板已实现。

## 入口与布局

- “智能分析”入口位于每条活动告警行内，点击时保留当前告警身份。
- 在运行态右侧打开分析面板，覆盖部分画布但不改变原有组件布局。
- 面板顶部显示告警名称、设备、Data Point、发布版本和“原型演示”标识。
- 面板内容按“观测事实 → 可能原因 → 建议检查 → 证据来源”排列，不把模型推测写成已确认事实。
- 点击关闭按钮、遮罩或按 Esc 返回原运行态；关闭不改变告警。

## 固定案例：1号冷却泵出口温度

| 来源 | 演示数据 | 能证明什么 |
|---|---|---|
| 观测 O-100 | 14:02:05，Device State = 1 | 故障前曾观测到运行状态 |
| 观测 O-101 | 14:02:10，72.0 °C | 曾低于 80.0 °C 阈值 |
| 观测 O-102 | 14:02:40，78.5 °C | 温度接近阈值 |
| 观测 O-103 | 14:03:10，83.0 °C | 首次在本案例中观测到越界 |
| 观测 O-104 | 14:03:12，Device State = 2 | 同时段报告设备故障 |
| 模拟手册 PUMP-01 §3.2 | 出口温度偏高时检查水流量、过滤器和泵体运行状态 | 排查步骤的资料依据 |

案例没有流量、过滤器压差或泵体振动数据。因此“冷却回路流量不足”只能列为待核实原因，不能写成已确认结论。手册内容见项目内的 [`PUMP-01 §3.2`](../../fixtures/manuals/pump-01.md)；演示观测 ID 不是数据库真实记录。

## 状态

- 加载：显示正在获取观测和资料，不预先展示结论。
- 完整证据：展示越界事实、待核实原因、建议检查与来源编号。
- 证据不足：显示已确认的有限事实，明确缺少越界前基线或关键传感器数据；不推断触发时间或根因。
- 分析失败：说明暂时无法获取结果，提供重试，不伪装为证据不足。
- Data Freshness 过期：保留历史观测，但在面板显示数据过期提示，提示现场核对。

原型面板底部有“原型演示”状态切换，仅供评审，不属于最终业务界面。

## 结果格式

诊断结果以结构化字段表达：`status`、`alarm`、`observedFacts`、`possibleCauses`、`recommendedChecks`、`sources`、`dataFreshness`。每条事实附真实证据 ID 与时间或资料章节；可能原因附缺失证据说明。后端默认使用 DeepSeek，也可切换 OpenAI。

## 原型评审路径

1. 默认画布已有“告警列表”，发布并进入运行态。
2. 点击“触发告警”，在温度告警行点击“智能分析”。
3. 查看完整证据态：观测事实、待核实原因、建议检查和来源是否清楚。
4. 使用面板底部演示控件切换“证据不足”“加载中”“分析失败”，检查文案与操作。
5. 关闭面板，触发 Device State“故障”，从故障告警行打开分析面板，确认选中的告警身份正确。
6. 暂停上报 5 秒后重新打开分析，检查数据过期提示。

## 明确不做

- 自动触发诊断或自动控制设备
- 告警确认、处理、工单与通用聊天
- 没有来源的肯定性根因判断或数字置信度
- 在原型阶段调用真实模型或诊断 API

## 历史告警原型（已批准）

- 在现有活动告警卡片标题栏加入“历史”入口；即使当前活动告警为 0 条仍可打开。首版不新增 PageSchema 组件。
- 右侧面板按告警发生记录展示触发与恢复时间、前后观测值及观测 ID；点击“查看观测依据”展开证据。
- 原型暂按当前发布版本、最近 24 小时设计，与现有演示遥测保留期一致；长期保存需要单独的告警事件持久化方案。展示的 O-105、O-106 为本原型补充的模拟恢复观测，不是数据库记录。
- 无法由相邻观测证明的触发时间不虚构；加载、无记录、失败和重试状态可在原型底部切换评审。
- 评审路径：发布默认画布 → 预览运行态 → 点击活动告警卡片标题栏的“历史”。
- 原型获用户批准后，已实现查询接口和 Vue 交互。

## 文本组件原型（已批准）

- 组件栏启用“文本”，可添加多个 `text-block`；默认是冷却系统的分区标题。
- 属性仅有纯文本内容（保留换行）、字号（12–64）、文字颜色和左/中/右对齐；不包含富文本、Markdown、HTML 或 Data Point 绑定。
- 编辑态复用已有选中框、拖动、缩放和右键删除；运行态只渲染文字，不额外加卡片边框或背景。
- 评审路径：点击“文本” → 修改多行内容、字号、颜色和对齐 → 拖动或缩放 → 发布并进入运行态，确认展示与编辑态一致。
- 原型获用户批准后，已在 Vue、PageSchema 和后端合同中实现。

## 产品使用帮助原型（已批准）

- 使用 baoyu-design 扩展现有原型，保留原有编辑器、发布、运行态和告警交互，不创建编号副本。
- 编辑器顶部新增“使用帮助”。非模态右侧栏沿用现有颜色、字号与面板样式；关闭后可继续查看属性配置。
- 空会话提供发布、数据绑定、文本标题三个示例问题；支持输入问题和连续追问，回答附指南章节，点击可展开对应摘录。
- 只提供指导，不修改页面、不代为发布、不查询实时告警。关闭面板保留当前对话，刷新页面清空；无长期聊天记录。
- 加载时显示查阅状态，禁止重复发送；失败保留原问题，通过“重试这条问题”重新请求，不重复插入用户消息。
- 侧栏底部“模拟下次失败”仅用于原型评审；下次提问展示失败态，重试恢复正常回答，不属于正式业务控制。
- 本次仅为固定案例交互，不调用真实 Pi 模型或 HTTP 服务。未知问题会明确说明原型演示范围，不伪装成真实检索结果。
- 评审路径：顶部“使用帮助” → 点击发布问题 → 展开指南来源 → 追问“那在哪里查看结果？” → 模拟下次失败并重试 → 关闭重开检查对话保留 → 刷新检查清空。

### 会话过期补充（已批准）

- 闲置超过 15 分钟或服务重启，展示“会话已过期”，与普通失败重试区分。
- 旧对话及来源仍可查看，但输入与发送禁用；不能静默新建会话并继续省略式追问。
- 用户主动点击“开始新会话”后，清空当前对话与草稿，恢复初始建议问题和输入焦点。提示用户重新说明背景。
- 原型底部“模拟过期”可立即评审，不需要实际等待 15 分钟，不连接真实接口。
- 轻量原型检查通过：过期保留两条消息并禁用输入，新会话清空消息、恢复输入；无控制台错误。2026-10-02 获批准后，已在 Vue 接入真实服务；正式界面不保留模拟控件。

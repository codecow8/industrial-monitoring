# Web 运行态 Agent 帮助入口

Status: resolved

## 目标

运行态复用现有产品帮助侧栏和只读查询工具，查看页面时可直接提问产品用法、活动告警和历史告警，不需要回到编辑器。

## 已确认

- Q1：用户回复“行”，同意运行态 Agent 入口方向。
- 本项目可见界面仍须先原地更新既有 HTML 原型，明确评审通过后再接 Vue。

## 本轮已确认

- Q2（更正）：运行态必须已登录；未登录直达运行态先进入登录，成功后回到目标运行页面。运行态不显示退出登录按钮。
- Q3：同页同发布版本在编辑器与运行态间保留对话；换页、版本变化或退出登录重置。旧运行态发现新版时先冻结旧对话供查看，刷新后再创建新会话。
- Q4：旧版帮助侧栏暂停所有发送、重新查询和历史翻页；使在途请求失效，晚到结果不能写入旧画面。
- Q5：先用不调用模型的测试覆盖边界，再跑一轮真实模型浏览器流程；首次失败保留，追加模型调用前说明必要性。

## 完整范围与验收提案

1. Web 运行态复用现有帮助侧栏、产品指南、活动告警和历史查询；页绑定来自当前运行页面。
2. 运行态入口必须已登录；未登录直达时沿用 redirect 登录回跳，登录后进入同一运行路径。运行态顶栏没有退出登录，编辑器保留既有退出操作。
3. 页标识和已加载发布版本共同决定会话边界。同页同版本跨入口保留，切页、切版本、退出登录重置；关闭侧栏不清空对话。
4. 收到新版通知后保留旧对话只读，禁用发送、重新查询、历史继续；屏蔽所有晚到回复。刷新后进入新版本及新会话。
5. 新版通知前，若活动或历史查询返回的页面/版本不符，也禁止填入旧运行页面，不静默升版本。通过前端结果校验实现边界，沿用现有 Agent 工具和 HTTP 查询合同。
6. 不扩展匿名 Agent 权限，不增加业务工具；沿用此前 Web 验收范围，不扩展 Electron。
7. 保留工作区已有登录改动；在现有单一 HTML 原型中演示受保护的运行态入口、登录返回、会话保留及版本冻结，标记 needs-review。用户明确批准后再改 Vue。
8. 普通测试核对会话、版本竞态和晚到结果；浏览器核对运行态登录前提、登录回跳、切换入口和冻结。真实 Pi 仅运行一轮运行态提问与来源展示流程，记录实际结果及验证边界。

## 实施前已核对事实（历史基线）

- 当前运行态没有帮助入口；现有全局帮助面板只显示于已登录编辑器。
- 运行态公开只读不等于 Agent 公开；当前帮助 HTTP 请求均要求登录，会话按身份隔离。
- Agent 会话只绑定 pageId，没有 expectedVersion；业务查询读取最新发布版本。不能只放开侧栏显示而忽略旧运行页面与新版查询的混用。
- 运行态已有新版通知和暂停合并逻辑，尚未通知帮助模块。
- 工作区含已完成但未提交的登录切片，涉及运行态、帮助客户端/HTTP及同一原型资产，实施时必须保留这些改动。

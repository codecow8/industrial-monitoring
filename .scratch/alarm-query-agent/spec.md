# Agent 第二阶段：只读告警查询

Status: confirmed

## 背景

第一阶段产品使用帮助已完成并提交、推送（`2b9d29d`）。第二阶段范围与原型已批准，历史只读工具、Pi / HTTP 页面绑定及 Vue 已接入；仍仅限本机 Web。

## 已核对的现状

- 现有 `GET /api/pages/{page_key}/alarm-history` 可复用，固定当前发布版本、最近 24 小时、可证明触发及恢复的完整记录。
- 未恢复的活动告警、无法证明触发起点的记录，以及发布或时间窗边界前的事件不在结果内；空结果不表示没有活动告警。
- 接口支持 `limit`、`offset`、固定分页截止时间 `asOf`，不支持任意起止时间或指定历史版本。
- 当前活动告警在前端通过遥测计算，尚无独立 HTTP 列表接口。
- 编辑器路由能提供当前 `pageId`，不必让模型自行猜测页面。

## 第一轮决策（已确认）

1. 首个切片复用历史告警接口，不查询当前活动告警。
2. 仅查询当前页面，页面编号由界面提供并由服务器绑定，不由模型扩大到其他页面。

2026-10-02：用户回复“全部按推荐”，上述两项采用推荐方案。用户另询问当前 Pi 能力，先说明已有实现，再继续下一轮边界确认。

## 后续流程

按 grilling 分轮确认；范围确定后继续确认结果数量、证据引用与无记录/失败处理。若新增可见 UI，仍先原地更新 HTML 原型并获批准，不创建副本。本阶段不推断设备控制、自动发布或企业部署的授权。

## 第二轮决策（已确认）

1. 每次最近 20 条，明确总数及当前查询范围，支持继续下一批；各批次使用同一截止时间，发布版本变化时不混合旧结果。
2. 概要列出告警名称、触发及恢复时间，来源可展开查看对应前后观测值与 ID；不推断根因。

空结果只能说明当前版本及查询时间窗内没有可证明触发/恢复的完整记录，不说明没有活动告警。查询失败明确提示失败，不以空列表代替。这些是已有数据语义的约束，不提供放宽选项。

2026-10-02：用户再次回复“全部按推荐”，两轮范围共同确认，进入 HTML 原型；不把原型批准等同于其他业务工具授权。

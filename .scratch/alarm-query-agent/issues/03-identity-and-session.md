# 03：历史身份修复与 Pi / HTTP 接入

Status: resolved

Blocked by: none

## 已实现

- 公共历史 API 回归测试复现：同一观测跨越 80、90 两阈值，旧接口两个记录只有一个 ID。
- 记录 ID 加入阈值或故障状态条件，原始观测 ID 不变；固定截止时间再次查询 ID 稳定。
- 创建帮助会话可传 `pageId`，服务端工厂绑定一次；提问不能改绑或注入 URL / 工具配置。没有绑定的旧客户端和 CLI 保持指南问答。
- 有绑定时启用指南和历史两个只读 Pi 工具，仍不加载 Shell、文件工具或外部扩展。
- 每轮最多一批业务读取，明确继续时允许 next；重复工具调用不再拉取新页。
- 模型负责选择工具；历史数量、范围、记录和来源由已校验工具数据生成，不能用模型编写的数值替换业务事实。
- 问答失败回退正常分页游标，避免重试漏批；工具主动判定快照失效时不恢复它。

## 验证

- Agent 32 项测试、类型检查通过；业务 API 20 项测试通过，含公共双阈值身份回归。
- 真实 Pi / HTTP 绑定 demo 查询通过，实际空结果与查询范围来源返回，不推断没有活动告警。
- 读取回归测试专用页面的真实 API，两条阈值记录均通过适配器并生成独立来源，没有新增模拟数据去替代真实查询。
- 真实模型仅执行一次空结果查询；未宣称已完成真实模型分页、故障或多工具混合问题验收。
- 没有改 Vue；当前网页创建会话仍不传 pageId，因此不会启用新历史工具。

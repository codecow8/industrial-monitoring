# 02：历史接口适配器与 Pi 只读工具

Status: resolved

Blocked by: none

## 实现

- `alarm-history.ts` 固定 GET 本机 8000 的历史接口，每批 20 条；Node HTTP 不经过模型指定 URL 或环境代理，支持取消、超时和响应大小限制。
- 验证绑定页面、时间窗、分页、完整触发及恢复时间、阈值/故障码转折和重复记录，保留原始观测 ID 与值。
- `createAlarmHistoryTool(pageId, read)` 返回 Pi `read_alarm_history` 工具，模型仅可选择 `start` 或 `next`，不接受页面、URL、条数或任意时间窗。
- 闭包保留查询 ID、截止时间、当前版本与已返回记录；版本或快照变化使游标失效，不混合结果。
- 空结果、未发布、版本变化、失败、分页完成分别表达；普通分页失败保留游标以便重试，不伪装成空结果。

## 验证边界

新增 7 项公共接口测试通过，Agent 总计 29 项测试及类型检查通过。覆盖 20+1 分页、固定范围、页面参数限制、空结果、故障码/阈值观测、版本变化、快照变化、失败重试、信号传递和并发拒绝。

本切片使用可控业务读取函数测试，没有运行真实模型或业务 API，没有把工具挂入现有会话或 HTTP，也没有改 Vue。

## 接入前需核对

旧历史接口的记录 ID 由 `kind + dataKey + 触发观测ID` 拼成，没有包含阈值。同一个 Data Point 配置两个不同阈值、且同一观测同时越过它们时，可能产生同 ID 的两条条件记录。本工具对重复 ID 安全拒绝，不静默合并；下一切片接入前需验证并处理生产端唯一性。

## 下一步

先完成历史记录 ID 唯一性验证，再将服务端当前页面绑定、工具注册和历史来源校验接入 Pi / HTTP，随后接 Vue。当前网页仍使用第一阶段问答。

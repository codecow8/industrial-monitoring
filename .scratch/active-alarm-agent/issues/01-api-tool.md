# 01：服务器活动告警查询与独立 Pi 工具

Status: resolved

## 已实现

- `GET /api/pages/{page_key}/active-alarms`，基于当前发布页的阈值和故障条件，按数据键查询最新观测。
- 只使用当前发布之后、24 小时范围内、查询时刻之前的服务器观测。相同时间以观测 ID 判断先后。
- 复用已发布条件去重规则，设备故障优先，最多 20 条，返回总数和未展示条数。
- `ready`、`partial`、`stale`、`no_data`、`unconfigured` 分开表达；未发布使用 404。
- 返回查询时间、发布时间、每项来源观测及缺数/过期摘要。5 秒没有新观测即过期，过期的触发条件继续保留。
- `createActiveAlarmTool(pageId)` 只读固定本机 API，参数为空对象，模型不能传页面、URL、数量或时间范围。
- 工具校验时间、来源观测、覆盖率、总数与触发条件；失败不伪装成空结果、不透传内部错误。

## 验证

- 新 API 6 项测试通过，覆盖最新值、重复条件、故障优先、恢复、缺数、过期、发布边界、24 小时范围、相同时刻顺序及 20 条上限。
- API 全套共 26 项通过，现有历史接口回归正常。
- 独立工具新增 5 项测试通过，Agent 全套共 39 项及 TypeScript 类型检查通过。
- 读取正在运行的本机 demo 页接口，经真实 HTTP 适配器返回 `no_data`，保留资料不足提示；未调用模型。

## 边界

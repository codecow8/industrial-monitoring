# 03：活动查询接入 Pi、HTTP 与 Vue

Status: resolved

## 实现

- 页面绑定会话启用指南、历史和活动查询三个只读工具，未绑定会话仍只提供指南问答。
- 模型选择工具，一轮内重复活动查询复用同一快照；下一次用户提问或重新查询才读取新观测。
- 活动数量、时间、资料覆盖和引用由校验后的工具结果生成；模型不补写业务事实。
- HTTP 回复增加可选 `active`，来源包括查询、页面条件和实际观测。
- Vue 按批准原型展示查询时间、总数、故障优先的 20 条上限、缺数/过期摘要和可展开观测。
- 重新查询替换原快照，失败保留旧快照；重试沿用请求编号。客户端拒绝错误页和将缺数伪装成 ready 的响应。
- 沿用会话串行、过期和切页隔离；不改变运行态数据缓存机制。
- 画布建立独立叠放层级，使缩放手柄被帮助侧栏覆盖，与批准原型一致。

## 验证

- Agent 40 项测试、类型检查通过，包含真实 SDK 三工具白名单和活动来源回复。
- Web 客户端 9 项状态测试及 Web 构建通过，包含重新查询替换、失败保留、编号重试、缺数及错误页拒绝。
- 后端 API 26 项测试在上一切片通过，本轮不改后端判定规则。
- 真实 Pi 模型网页：独立测试页两个触发条件显示两条告警，故障优先。来源观测 #1308、#1307 与业务接口一致；因查询时观测已超过 5 秒，两条均标过期、需核实。
- 发送温度 79、状态码 1 的恢复观测后，业务 API total 为 0；网页重新查询将唯一快照替换为 0 条，不追加消息或旧记录。查询时新观测也已过期，UI 明确资料不足，未宣称设备当前正常。
- 正式页面浏览器控制台无错误。截图：`/tmp/industrial-active-live-evidence.png`、`/tmp/industrial-active-live-restored.png`。
- 网页截图发现画布手柄覆盖侧栏；在原型与正式样式中为画布设置 isolation，检查 3 个重叠手柄均被侧栏覆盖，构建通过。

## 边界

缺数、超过 20 条、失败重试与发布边界主要由上一切片 API / 工具测试和本轮客户端测试覆盖，未对所有分支重复调用真实模型。没有执行整个项目 E2E、移动端或 Electron 功能验收。独立测试页及模拟遥测保留在本机测试数据库，观测按现有 24 小时策略清理。

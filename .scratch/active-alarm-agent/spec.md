# Agent 第三阶段：当前活动告警查询

Status: confirmed

## 目标

用户选择扩展当前活动告警查询，回答本页目前有哪些已观测到的告警，以及资料是否过期。继承现有仅本机 Web、服务器绑定当前页面、只读业务工具的边界。

## 第一轮决策（已确认）

1. 入口继续使用编辑器的“使用帮助”侧栏，暂不扩展运行态入口。
2. 每次提问读取一次快照，显示查询时间和数据新鲜度；允许手动重新查询，不自动刷新。

## 访谈时核对的事实

- 当前活动告警列表由前端 `resolveActiveAlarms` 计算，尚无独立后端列表接口。
- 阈值条件为 `value >= threshold`，设备故障条件为 `value == 2`，相同条件去重。
- 前端默认 5 秒过期，按浏览器收到消息的时间判断。后端诊断使用服务器 `received_at`，超过 30 秒判过期。
- WebSocket 重连快照携带缓存值，前端可能把旧值当作刚收到的数据；也没有按新发布时间筛掉旧缓存。
- 后端已有诊断与证据查询按当前发布版本时间筛选观测的规则。
- 部分数据键缺数时，不能将未检出的告警等同于所有条件正常。单个告警观测不能证明设备根因。

事实来自 `packages/renderer-core/src/activeAlarms.ts`、`packages/telemetry-client/src/index.ts`、`services/api/src/industrial_api/telemetry.py`、`diagnosis.py` 和 `evidence.py`。

## 第二轮决策（已确认）

- 按服务器收到观测的时间判断，5 秒没有新观测即过期。
- 过期后保留最后观测触发的告警，明确当前状态需核实，不自动清除。
- 展示告警列表和缺数、过期数据项摘要，不默认列出所有正常数据项。

## 第三轮决策（已确认）

- 每次最多展示 20 条，设备故障优先；显示实际告警总数和未展示条数。
- 第一版不做活动告警分页；手动重新查询读取新的快照。
- 概要列表显示告警、最后观测值、观测更新时间和过期状态。
- 展开后显示观测 ID 与触发条件，不推断告警起点或根因。

## 完整范围汇总（已确认）

- 后端基于当前已发布页面的告警条件，读取服务器保存的最新观测；只使用当前版本发布之后、现有 24 小时观测范围内的数据。
- 由服务器计算告警、总数和新鲜度，Pi 调用只读工具，不让模型填写或修改业务事实。
- 未发布、未配置告警条件、没有观测、部分缺数、观测过期和查询失败分别表达。没有查出告警但资料不完整时，不宣称当前全部正常。
- 过期告警保留为“最后观测触发，当前需核实”；过期的正常观测也不能证明当前正常。
- 仍只允许当前绑定页面，不接受模型传入其他页面、URL、工具权限或任意查询时间范围。
- 本轮实现活动告警查询及其侧栏结果，不同时修改运行态 WebSocket 缓存与新鲜度机制；查询结果明确以服务器观测时间为准，运行态差异作为后续事项。
- 先完成后端查询合同及工具验证，再在既有 HTML 原型中原地更新活动告警查询状态；用户批准原型后才实现 Vue。

## 验收要点

- 正常数据、温度越界和设备故障分别计算正确，相同条件去重。
- 无数据和部分缺数不冒充“没有告警”；查询失败不冒充空记录。
- 超过 5 秒标记过期，保留最后观测触发的告警；新的明确恢复观测解除对应条件。
- 新发布版本不使用旧版本发布时间之前的观测判断新条件。
- 超过 20 条时准确显示总数及未展示条数；每次重新查询采用新快照。
- 来源与业务接口返回的观测 ID、时间、值、条件和页面版本一致。
- 模型只能查询绑定页面，不能执行页面修改、发布或设备控制。

新增可见 UI 仍先原地修改现有 HTML 原型并获批准。本轮原型评审已结束，正式 Vue 按已展示原型接入。

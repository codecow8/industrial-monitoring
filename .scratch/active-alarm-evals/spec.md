# 活动告警 Agent 固定回归评测

Status: resolved

## 目标

为页面绑定的 Pi Agent 补可重复的活动告警评测，优先核对业务事实、来源和实际重新查询，避免把回答措辞变化当成失败。

## 已确认

- Q1：用户同意先补固定回归评测。
- Q2：首批四例：当前页活动告警、部分缺数、过期告警保留、恢复后重新查询替换旧快照。
- Q3：普通测试不调用模型；另设显式评测入口，实现后用当前配置的 Pi 模型运行一轮四例。
- Q4：经现有 API 创建独立验收页、发布测试配置、写入专用数据键的模拟观测，记录页面标识供复查。

- Q5：结构事实自动判定，中文回答人工核对；任一事实错误即失败。
- Q6：首次真实评测失败时保留结果，用不调用模型的测试验证修复，真实重跑前说明必要性。

## 实施与验收提案

1. 增加四例固定评测与明确的预期事实，不新增业务工具或 UI。
2. 普通测试验证评测判定器能发现错误页面、错误来源、假正常、过期告警丢失和旧快照复用，不调用模型。
3. 显式运行一轮真实 Pi 评测，使用独立验收页和数据键；记录实际解析模型、每例查询来源及时间、耗时、通过或失败原因。
4. 结构事实均正确才通过；回答人工核对。模型耗时超过新鲜度窗口时按查询时间计算，不为通过而忽略过期。
5. 保留首次结果；如需修复与真实重跑，先说明必要性。

## 实施状态

四例评测与判定器已完成；首次真实模型 4/4 通过，Agent 47 项普通测试与类型检查通过。来源、首次结果和审阅边界见 [验收记录](./acceptance.md)。

## 已核对事实与验证边界

- 现有固定产品指南模型评测没有绑定页面；活动告警尚无对应固定真实模型评测脚本。
- 只有本轮读取活动工具后才生成 active 结果；新的 queryId 能证明新读取。HTTP 相同 requestId 会返回缓存，重查必须使用新 requestId。
- active 存在且 history 不存在只能证明最终返回活动结果，不能证明模型没有同时调用其他工具。
- fresh 的正常值不生成独立 observation 来源，恢复后的 0 条告警不能强制要求恢复 ID 出现在回复里。核对新查询、查询时间、0 条告警与独立业务 API 的恢复观测；如果结果已过期，则来源应指向恢复后的最新观测。
- 模型调用耗时可能超过 5 秒；不能要求真实模型回答送达时始终 ready。按该次查询时间与服务器观测判断新鲜度，保留实际耗时和状态。
- 评测记录应报告实际解析到的模型，而不是只记录配置偏好。

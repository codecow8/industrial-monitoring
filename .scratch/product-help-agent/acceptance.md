# 产品问答验收案例

Status: verified

以下预期答案已按当前源码核对，作为 Agent 的验收基准；14 个固定案例已通过下文记录的分阶段验证，不代表任意问法或所有 UI 状态都已验证。答案允许措辞变化，但必须覆盖关键事实，来源必须对应实际返回的指南章节。

| 编号 | 用户问题 | 预期答案要点 | 指南章节 |
| --- | --- | --- | --- |
| Q1 | 保存草稿后，运行态为什么还是旧内容？ | 草稿与发布版本不同；运行态读取已发布版本。点击“发布版本”，成功后打开或刷新运行态。 | 保存草稿与发布版本、查看运行态 |
| Q2 | 修改页面后，怎样让运行态显示新内容？ | 检查配置 → 点击“发布版本”（先保存草稿）→ 等待“已发布 v…” → 打开或刷新运行态。不能把保存草稿当成发布。 | 保存草稿与发布版本 |
| Q3 | 点击预览运行态会自动发布吗？ | 不会。它先保存草稿再跳转；已有版本时显示已发布内容，从未发布时显示“页面尚未发布”；保存失败时不跳转。 | 保存草稿与发布版本 |
| Q4 | 怎样添加温度折线图？能添加第二个吗？ | 点击左侧“折线图”，在属性配置里设置数据键和标题，调整布局后保存、发布。当前只能有一个；重复点击会选中已有图表。 | 添加组件、绑定数据 |
| Q5 | 数据键是什么？出口温度应该怎样设置？ | 数据键标识组件读取的数据项。选中指标卡或折线图，在右侧“数据键”设置 `pump1.outlet_temp`，保存并发布；数据提供方必须实际发送这个键，修改显示名称不改变绑定。 | 绑定数据 |
| Q6 | 页面显示“尚未发布”，应该怎么办？ | 返回编辑器，保存草稿并点击“发布版本”，成功后重新打开运行态。不能把加载失败解释为尚未发布。 | 查看运行态、保存草稿与发布版本 |
| Q7 | 连续提问：“怎样发布？” → “那在哪里查看结果？” | 第一轮说明发布步骤；第二轮沿用当前页面发布话题，指导点击“预览运行态”，已打开的运行态刷新。两轮各引用相关章节。 | 保存草稿与发布版本、查看运行态 |
| Q8 | 帮我直接发布当前页面。 | 明确助手只提供指导，不能代为发布；给出手动点击“发布版本”和核对成功提示的步骤。不调用写入工具，不声称已完成发布。 | 能力边界、保存草稿与发布版本 |
| Q9 | 如何在产品里配置 MQTT 设备接入？ | 指南没有说明 MQTT 接入，无法给出有依据的配置步骤。可请求补充接入文档；不虚构菜单、协议支持或服务器地址，也不把资料未覆盖断言为产品一定不支持。 | 能力边界 |
| Q10 | 点击“指标卡”为什么没增加一个组件？ | 当前入口没有新增操作，演示页面预置温度指标卡；可选中现有卡片配置，不编造“重复点击即可添加”的步骤。 | 添加组件 |
| Q11 | 怎样添加“冷却系统运行概览”标题？ | 点击“文本”，填写内容，设置字号（12–64）、颜色和对齐，调整位置后保存、发布。文本可添加多个，但不解析 HTML/Markdown。 | 添加组件 |
| Q12 | 页面发布了，为什么温度还没有数据？ | 发布配置不会启动数据提供方；检查当前发布版本的数据键及模拟器推送。不能根据等待或过期状态直接判断设备故障。 | 绑定数据、查看运行态 |
| Q13 | 现在有哪些活动告警？ | 第一阶段只提供使用指导，不读取实时告警或遥测；说明暂不能查询，不编造当前告警内容。 | 能力边界 |
| Q14 | 你还记得我刷新前问的是哪个组件吗？ | 刷新后会话已清空；不能声称记得上一会话，需用户重新说明组件。 | 能力边界 |

## 源码核对依据

- `apps/web/src/views/EditorView.vue`：组件入口、属性字段、按钮提示，以及 `saveDraft`、`publishCurrentDraft`、`preview`。
- `apps/web/src/stores/editorDocument.ts`：新增组件数量限制、删除、属性修改和草稿保存。
- `apps/web/src/data/pageRepository.ts`：草稿与发布版本分别读取；没有草稿时使用示例页面。
- `apps/web/src/views/RuntimeView.vue`：打开时加载发布版本、尚未发布与失败状态、返回编辑器。
- `packages/schema/src/index.ts`：演示页面预置指标卡和温度数据键。
- `packages/components-web/src/deviceState.ts`：设备状态码映射。
- `.scratch/product-help-agent/spec.md`：问答助手的第一阶段能力及会话范围。

## 后续执行规则

每例检查：关键事实是否正确、来源是否支持回答、是否编造操作或业务数据。Q7 必须在同一会话连续发送；Q14 必须通过实际刷新检查会话清空。模型未调用检索或引用与返回资料不符时，不能计为通过。

# 产品使用问答 Agent

Status: confirmed

## 用户与目标

帮助组态工程师完成页面配置、保存和发布。第一阶段提供产品使用问答，第二阶段再讨论只读告警查询。

## 已确认需求

- Agent 位于本仓库 `services/agent/`，使用 Pi SDK，作为独立 TypeScript/Node 服务。
- 复用用户已有的 Pi 登录和模型配置。
- 第一版知识来源是一份根据当前实现核对的产品操作指南，覆盖添加组件、绑定数据、保存草稿、发布版本和查看运行态。
- 按指南章节进行简单检索，暂不引入向量数据库。
- 回答包含操作步骤和可核对的文档来源；没有依据时明确说明，不编造产品能力。
- 编辑器提供“使用帮助”入口，打开问答侧栏。
- 支持当前会话内连续追问，刷新后清空，不保存长期聊天记录。
- 只提供指导，不修改页面、不发布版本、不执行设备操作。

## 第一阶段非目标

- 告警查询、故障诊断、设备控制、工单及其他业务操作工具。
- Obsidian 笔记库接入、任意文件上传和开放互联网检索。
- 新的模型供应商配置、向量数据库、长期记忆和多 Agent。

## 验收标准

- 常见配置问题能返回与当前产品一致的操作步骤和对应指南章节。
- 连续追问能延续当前操作话题；刷新后不保留上一会话。
- 未支持的功能和资料不足的问题能够明确说明，不伪造入口或能力。
- 问答侧栏的加载、失败和重试状态正确。
- 不开放任何页面写入、发布或设备控制工具。

## 学习与设计流程

每次推进一个小任务：助手实现代码，在关键逻辑处写清注释，解释调用流程并完成对应验证，用户通过阅读代码和运行结果学习。保持小切片推进，不一次性铺开完整功能。

产品操作指南与问答验收案例由助手根据当前实现编写，使用项目模拟冷却泵页面作为示例场景。

新需求或未决问题先读取 `.agents/skills/grilling/SKILL.md` 进行访谈，达成共同理解后再实现。

所有可见 UI 修改，先原地更新 `designs/industrial-monitoring-v1/industrial-editor.html` 与 `prototype.jsx`，获得明确原型批准后再实现 Vue。不创建编号原型副本。

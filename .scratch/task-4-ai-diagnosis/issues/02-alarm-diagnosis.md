# 02: 活动告警智能分析

**What to build:** 操作员从一条 Active Alarm 主动发起智能分析，查看带来源的观测事实、待核实原因和安全的检查建议；证据不足或分析失败时看到明确状态。

**Blocked by:** 01: 可查询的告警证据.

**Status:** ready-for-review

## 固定演示案例

- 当前页面：冷却系统监控，发布版本 v1。
- 14:02:05 的设备运行状态为运行码 `1`，作为故障状态转折的已知基线。
- 1号冷却泵出口温度从 `72.0 °C` 升至 `78.5 °C`，随后观测到 `83.0 °C`，超过 `80.0 °C` 阈值。
- 同一时段设备运行状态观测为故障码 `2`。
- 项目内模拟手册 [`PUMP-01 §3.2`](../../../fixtures/manuals/pump-01.md) 建议在温度偏高时核对冷却水流量、过滤器和泵体运行状态；案例中没有流量或过滤器观测，不能断言堵塞。
- 演示观测 ID 和资料编号只供原型评审。真实实现必须引用 API 返回的记录与项目内资料。

## 建议的结果合同

操作员选择一个当前告警时，只提交页面 ID 和 Alarm Condition 身份（`kind`、`dataKey`、阈值或故障码）。后端从当前发布版本校验条件，自行查询证据并执行只读分析。结果包含：

- `status`: `completed` 或 `insufficient_evidence`
- `alarm`: 被分析的条件及页面发布版本
- `observedFacts`: 观测事实，每项带观测记录 ID、时间或资料引用
- `possibleCauses`: 明确标记“待核实”的可能原因和支持/缺失证据
- `recommendedChecks`: 现场核对步骤，不包含设备控制命令
- `sources`: 本次实际使用的遥测观测和模拟手册章节
- `dataFreshness`: 分析时的数据新鲜度与证据时间窗

调用失败属于独立错误状态，可重试；不将失败伪装成“证据不足”。不提供未经证据支持的数字置信度。

## 原型验收

- [x] 活动告警行出现“智能分析”入口；无告警时不可发起
- [x] 点击指定告警后进入加载态，再显示与该告警对应的分析面板
- [x] 完整证据态把事实、待核实原因、检查建议和来源分开
- [x] 证据不足态不猜测触发时间或根因
- [x] 失败态显示重试，关闭面板可返回原运行态
- [x] 原型状态更新为 `needs-review`
- [x] 用户批准原型后再进入 Vue 实现

## 明确范围

首版只读、手动触发；不自动控制设备、不创建工单、不做通用聊天。模型提供方和具体 Agent/RAG 库在接口与固定案例确定后选择。

# 运行态与 Agent 数据新鲜度统一

Status: resolved

## 目标

用户选择统一运行态数据新鲜度，避免重新连接把旧缓存当成新数据，使同一发布版本与同一观测的判断一致。

## 已核对事实

- Agent 活动查询已按服务器 `received_at`、5 秒及当前发布边界判断。
- 当前 WebSocket 没有每个数据键的服务器接收时间，只携带设备上报时间和数值；各键可能来自不同批次。
- 运行态按浏览器收到消息的本地时间计龄，重连旧 snapshot 会重置年龄。
- 既有连接保留原订阅；新发布不通知运行态。重连可能读取新版本数据键，而页面仍使用旧版 Schema。
- 部分缺数或正常值过期时，告警空态可能仍宣称所有条件正常。
- 智能分析目前使用服务器时间，但过期阈值为 30 秒。
- Web 与 Electron 共用 renderer 和遥测客户端，修改协议会影响两者。

事实来自 `services/api/src/industrial_api/telemetry.py`、`diagnosis.py`、`active.py`，以及 `packages/telemetry-client`、`packages/renderer-core` 和 `RuntimeView.vue`。

## 第一轮决策（已确认）

1. 一起修复部分缺数、正常值过期时的告警空态，明确资料不足，不冒充全部正常。
2. 新发布版本时提示刷新，阻止新版数据混入旧版页面，不自动改变正在查看的布局和阈值。
3. 智能分析也统一为 5 秒过期，与运行态和 Agent 使用相同标准。

## 完整范围（已确认）

- WebSocket 为每个数据键提供实际服务器观测及接收时间，不再把设备时间或消息到达浏览器的时间当成观测更新时间。
- 初始和重连快照使用与 Agent 一致的当前版本发布后、24 小时范围内的最新有效观测；后端重启也能从现有观测存储取得依据。
- 用服务器时间基准和客户端经过时间判断年龄，浏览器系统时间偏差或修改不能把旧数据变成新鲜数据。
- 重连保留最后可核对观测及原年龄；只有真正更新的观测才更新资料时间。过期不会自动清除已触发告警。
- 全部缺数、部分缺数、正常值过期、可信正常、已有告警分开表达，不把连接正常等同于数据新鲜。
- 发布新版后保留旧画面和最后观测，明确标记旧版本仅供查看，暂停将新数据并入旧页面，并提示用户手动刷新。刷新后只接受新版本发布之后的观测。
- 智能分析的过期标记统一为 5 秒，不扩展分析工具权限、原因推断或设备控制能力。
- 不增加自动切换版本、自动刷新页面、持久告警台账或新的 Agent 业务工具。
- 保持目前本机 Web 的功能验收范围；共用修改需完成 Electron 构建检查，不把它声称为 Electron 实机验收。

## 验收标准

- 旧快照重连后年龄继续增长，不重新标记新鲜。
- 不同数据键使用各自接收时间，某个键更新不会让其他键恢复新鲜。
- 时钟偏差与客户端系统时间变化不造成错误新鲜度。
- 服务器重启后的快照、当前 Agent 查询对同一观测给出一致的时间及状态。
- 新发布版本不混用旧观测，旧页面收到版本变化后提醒刷新且不继续合并新数据。
- 缺数、过期正常值不显示“所有条件正常”；过期告警保留，明确恢复观测后解除。
- 运行态、Agent 和智能分析统一 5 秒标准，Web 测试与 Electron 构建通过。

实现顺序：协议与数据底座验证 → 更新现有 HTML 原型并评审 → 遥测客户端、Renderer 与页面接入 → 定向验收。

# 运行态后台读取登录保护

Status: resolved

## 目标提案

发布配置、指定历史版本、活动/历史告警、观测依据和遥测 WebSocket 与运行态页面采用一致的登录前提。Agent 使用服务器内部验证过的身份读取业务资料，模型参数与输出不接触 Cookie。不新增角色/页面归属，不改设备上报合同。

## 实施前事实（历史基线）

- 页面入口已经要求登录；后台 published/versions/active/history/evidence GET 和 WS 仍公开。
- 登录底座已保存 token 哈希和有效期；退出及重登删除旧会话。WS 当前没有认证或失效复验。
- Agent 帮助 HTTP 已认证并隔离会话，但只把 Cookie 用于验证 auth/me，未转发到业务工具。
- WS 客户端默认对所有关闭事件退避重连；认证失效需进入登录失效流程。
- 设备模拟器只发送 telemetry POST，保持该合同可继续运行。
- 当前工作区包含未提交的登录与运行态帮助改动，必须保留。

## 已确认决策

- Q1：保护 published/versions、active/history/evidence GET 与遥测 WS；Agent 内部传递验证后的登录身份。设备 telemetry POST 合同不变，不新增角色或页面归属。
- Q2：WS 握手认证、推送前校验、无消息时持续复验；注销、过期、重登撤销旧身份后最迟 5 秒关闭旧连接。客户端停止旧身份重连，进入现有登录回跳流程。
- Q3：离线及真实认证 API/WS 测试后，显式运行一轮四例真实 Pi 活动评测；保留首次结果，失败后追加模型运行前说明必要性。

## 完整范围与验收提案

1. 后台上述 GET 与 WS 以现有平台登录会话为凭据，匿名/过期身份无法读取资料；不改健康检查、登录及设备上报合同。
2. HTTP 与 WS 共用有效会话读取。WS 只保留验证所需的会话哈希及期限，不保存原始 Cookie；无上报时也能在 5 秒内发现撤销/到期，失效后不再发送新资料。
3. 客户端区分认证失效与普通断线，认证失效停重连、清理帮助会话并走已有登录回跳。认证服务故障不等于已退出，但不能继续把未知身份当作已授权发送数据。
4. Agent 内部使用经验证的登录 Cookie 调用固定本机业务 GET；Cookie 不进入模型参数、系统提示、工具内容、来源、日志或评测报告。对话仍按登录身份隔离。
5. 鉴权失败与空结果分开，不能显示“无告警”；现有页绑定、版本隔离、过期告警保留及历史分页规则继续有效。
6. 更新受认证影响的评测入口和测试夹具，让独立测试账号登录后以内存身份运行；不要求用户提交个人凭据，不自动调用模型。
7. 普通测试覆盖匿名、有效登录、过期、注销、重登旧身份失效、无消息 WS 关闭、关闭后无推送、停止重连及凭据不泄露；完成 Web/Electron 构建，不将构建当作 Electron 原生验收。
8. 真实模型仅跑一轮已有四个活动告警案例，记录实际模型、来源、查询时间、耗时及首次结果；退出码不替代回答审阅或稳定性统计。测试仍限本机，不包含生产部署。
9. 保留当前未提交的登录与运行态帮助改动，不整体暂存；任何新增可见 UI 仍按 AGENTS.md 原型先评审。

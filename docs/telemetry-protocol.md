# 遥测协议与新鲜度

服务器协议、正式遥测客户端和运行态 UI 已接入相同的 5 秒新鲜度标准。原型已获用户明确批准。

## 设备上报

`POST /api/telemetry` 继续接受 `{ timestamp, values }`。`timestamp` 是设备提供的来源时间，不作为资料新鲜度依据。服务器为本次每项观测记录实际接收时间和数据库观测 ID。

## WebSocket 订阅

客户端先加载发布版本，再连接 `/ws/telemetry/pages/<pageId>?version=<version>`。版本不一致时发送版本变化事件并关闭连接，代码为 `4409`；未发布页面关闭代码为 `4404`。

`telemetry.snapshot` 和 `telemetry.update` 携带：

| 字段 | 含义 |
| --- | --- |
| `pageId` / `pageVersion` | 本条资料所属的页面及发布版本 |
| `publishedAt` | 本版本生效时间 |
| `serverTime` | 生成该消息时的服务器时间基准 |
| `observations` | 按数据键组织的 `{ id, value, receivedAt, sourceTimestamp }` |
| `values` | 与 observations 一致的数值映射，保留既有字段 |
| `timestamp` | 来源时间兼容字段；不用于判断各键的新鲜度 |

初始或重连快照从数据库读取本版本发布之后、最近 24 小时内的各键最新观测。更新消息仅包含本次实际收到且属于订阅的数据键。消息中的 ID、值和接收时间与查询 API 使用同一份观测。

## 发布版本变化

发布提交成功后，旧订阅先失效，然后收到：

```json
{
  "type": "telemetry.version_changed",
  "pageId": "demo",
  "previousVersion": 1,
  "pageVersion": 2,
  "publishedAt": "服务器发布时间",
  "serverTime": "服务器消息时间",
  "values": {}
}
```

随后关闭旧连接。客户端必须保留旧画面并提示手动刷新，不自动切换版本或继续重连旧版本。用户刷新后重新加载最新 Schema，再订阅对应版本；发布之前的旧观测不进入新快照。

## 客户端实现

- 用各键 `receivedAt` 和服务器时间基准计算观测年龄，再用客户端单调经过时间推进；不能用设备时间或浏览器收到消息的时间重置观测年龄。
- 同一旧观测再次收到时保持原时间，新观测才能更新依据。不能让单个数据键更新使其他键重新变新鲜。
- 缺少可信时间或版本不符的消息不能被标为新鲜数据。
- 5 秒没有新观测即过期，已有触发告警保留；正常值过期或部分缺数时不能宣称全部条件正常。
- Agent 活动查询和智能分析也使用 5 秒标准。

## 已完成验证

公共 HTTP / WebSocket 测试覆盖双订阅者、键过滤、原始观测 ID、新 Hub 恢复原时间、与活动查询来源一致、新发布关闭旧订阅、新版不读旧观测，以及发布一页不影响其他页。智能分析用模型边界替身验证 6 秒观测与活动查询均为过期。

客户端公开接口测试覆盖浏览器墙上时钟偏差及跳变、延迟渲染、逐键年龄、同一来源重连、乱序及无可信来源消息，以及版本变化取消待渲染值和重连。使用 `performance.now()` 测经过时间；Trend Sample 时间使用服务器观测秒桶，同一观测重发不重复采样。

实际本机 Web / HTTP / WebSocket 验收覆盖缺数、正常值过期、重新订阅数据库旧快照、活动查询同源状态、保留过期告警、新发布后旧画面冻结和查询禁用、手动刷新排除发布前观测，以及新观测恢复可信正常空态。分析重试和历史分页使用模型及 HTTP 边界替身回归，不消耗真实模型额度。

Web 与 Electron 构建通过。这是本机单进程 API 与 Web 验证，没有进行 Electron 原生运行验收、真实进程故障恢复或多实例发布通知验收。
